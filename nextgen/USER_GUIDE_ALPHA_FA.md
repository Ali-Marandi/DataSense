# راهنمای کاربر DataSense NextGen Alpha

**نسخه:** `nextgen-v0.1.0-alpha`  
**مخاطب:** تحلیل‌گران داده، تیم‌های عملیات و کاربران آزمایشی که می‌خواهند دادهٔ محلی را بررسی، اعتبارسنجی و با یک رسید اعتماد خروجی بگیرند.

> **وضعیت Alpha:** این نسخه برای ارزیابی کنترل‌شده طراحی شده است. برنامه به‌صورت local-first عمل می‌کند؛ دادهٔ خام CSV برای تحلیل، کیفیت‌سنجی و خروجی در فرایند محلی برنامه باقی می‌ماند. نسخهٔ جاری ممکن است بدون امضای کد Windows منتشر شده باشد؛ پیش از نصب، `SHA256SUMS.txt` را بررسی کنید و هشدار ناشر ناشناس Windows را با دقت ارزیابی کنید.

## ۱. شروع سریع

ابتدا از صفحهٔ Release فایل `DataSense-…-windows-x64-setup.exe` را برای نصب، یا فایل `DataSense-…-windows-x64-portable.zip` را برای اجرای قابل‌حمل دریافت کنید. installer برنامه را برای کاربر فعلی نصب می‌کند؛ نسخهٔ portable را باید ابتدا در یک پوشهٔ قابل‌نوشتن استخراج کنید و سپس `DataSense.exe` را اجرا نمایید.

| روش | مناسب برای | اقدام |
|---|---|---|
| Installer | استفادهٔ روزمره روی یک رایانهٔ شخصی | اجرای setup، انتخاب مسیر پیش‌فرض و اجرای برنامه از Start Menu |
| Portable ZIP | ارزیابی کوتاه‌مدت یا محیط بدون نصب | استخراج ZIP، بررسی checksum و اجرای `DataSense.exe` |

پس از باز شدن برنامه، روی **Load sample** بزنید تا گردش‌کار را با دادهٔ نمونهٔ غیرحساس امتحان کنید. برای کار با دادهٔ خود، روی **Open CSV** یا **Open local CSV** کلیک کرده و یک فایل `CSV`، `TSV` یا `TXT` محلی را انتخاب کنید.

## ۲. مدل حریم‌خصوصی و امنیت

DataSense Alpha برای این طراحی شده که دادهٔ raw را به سرویس آنلاین منتقل نکند. جدول preview، dashboard و خروجی HTML در همان دستگاه ساخته می‌شوند. telemetry در Alpha به‌صورت opt-in است و مسیرهای UI موجود آن را با رضایت `false` فراخوانی می‌کنند؛ بنابراین eventهای عملیاتی به‌طور پیش‌فرض ارسال یا صف‌بندی نمی‌شوند.

| دارایی | محل/رفتار | دادهٔ خام دارد؟ |
|---|---|---|
| Dataset فعال | حافظهٔ فرایند برنامه | بله؛ فقط محلی |
| Preview | حداکثر ۱۰۰ ردیف در UI | بله؛ فقط روی صفحهٔ محلی |
| Dashboard/Profile | شمارش‌ها و aggregateها | خیر |
| Verified receipt | JSON امضاشده کنار خروجی | خیر؛ فقط metadata و hash |
| Application log | JSONL چرخشی محلی | نباید داشته باشد؛ متن با redaction پایه ذخیره می‌شود |
| Error record | JSONL محلی با error ID | خیر؛ متن خطا و context redacted |

> **قاعدهٔ عملی:** فایل‌های log یا error را قبل از ارسال به پشتیبانی بازبینی کنید. redaction یک لایهٔ دفاعی است و جایگزین عدم ثبت دادهٔ خام در متن خطا یا نام فایل نیست.

## ۳. گردش کار اصلی

### ۳.۱ Explore: بازکردن و مرور داده

در بخش **Explore** یک فایل محلی باز کنید. برنامه صحت اولیهٔ مسیر، پسوند، parser و خالی نبودن داده را بررسی می‌کند. پس از import، وضعیت dataset، profile aggregate و preview محدود نمایش داده می‌شود.

| کنترل اولیه | نتیجهٔ مورد انتظار | اقدام در صورت خطا |
|---|---|---|
| پسوند | CSV، TSV یا TXT | فایل را به فرمت delimiter-separated تبدیل کنید. |
| ستون‌ها | نام ستون یکتا | نام‌های تکراری را قبل از import اصلاح کنید. |
| داده | حداقل یک ردیف | header و encoding فایل را بررسی کنید. |
| delimiter/encoding | قابل‌خواندن بودن فایل | فایل را با UTF-8 ذخیره کنید یا delimiter را استاندارد کنید. |

### ۳.۲ Prepare & Validate: کنترل کیفیت

روی **Run quality checks** کلیک کنید. DataSense قرارداد کیفیت محلی فعال را اجرا می‌کند. نتیجه شامل نام rule، severity، وضعیت، تعداد violation و توضیح aggregate است. شکست ruleهای `critical` و `high` مسیر خروجی تأییدشده را مسدود می‌کند؛ ruleهای `medium` و `low` هشدار هستند و در تصمیم export ثبت می‌شوند.

> **تفاوت مهم:** قبولی در quality check به معنی درست‌بودن کسب‌وکاری همهٔ داده‌ها نیست؛ فقط نشان می‌دهد قرارداد فعلی بدون finding مسدودکننده عبور کرده است.

### ۳.۳ Data readiness: تحلیل آمادگی داده

دکمهٔ **Run data readiness insights** یک تحلیل توصیفی محلی انجام می‌دهد. این ماژول داده را تغییر نمی‌دهد، مقدارهای سلولی را نمایش نمی‌دهد و هیچ سیگنال سرمایه‌گذاری یا پیش‌بینی تولید نمی‌کند.

| شاخص | معنا | تفسیر پیشنهادی |
|---|---|---|
| Readiness score | امتیاز ۰ تا ۱۰۰ از completeness، identifierهای احتمالی و outlierهای IQR | زیر ۷۰ یعنی پیش از تحلیل بعدی dataset را مرور کنید. |
| Columns with missing values | شمار ستون‌های دارای مقدار مفقود | سیاست حذف/اصلاح/غنی‌سازی داده را مشخص کنید. |
| High-cardinality columns | ستون‌های غیرعددی با نسبت مقادیر یکتا بالا | احتمال identifier بودن را بررسی کنید؛ لزوماً خطا نیست. |
| IQR outlier observations | تعداد مشاهده‌های numeric خارج از بازهٔ IQR | outlier می‌تواند خطای ورود یا رخداد واقعی باشد؛ حذف خودکار انجام نمی‌شود. |

### ۳.۴ Deliver: خروجی تأییدشده

پس از اجرای quality check، به بخش **Deliver** بروید و **Export verified HTML report** را انتخاب کنید. اگر قرارداد کیفیت مسدود نشده باشد، برنامه فایل HTML aggregate-only و یک فایل receipt JSON امضاشده می‌سازد. اگر یافتهٔ blocking وجود داشته باشد، HTML تولید نمی‌شود اما decision receipt نوشته می‌شود تا دلیل تصمیم ثبت باقی بماند.

| نتیجه | artifact HTML | receipt | گام بعدی |
|---|---|---|---|
| Approved | ساخته می‌شود | ساخته می‌شود | receipt را نگه دارید و در صورت نیاز verify کنید. |
| Blocked | ساخته نمی‌شود | ساخته می‌شود | findingهای critical/high را اصلاح و دوباره quality check را اجرا کنید. |

برای بررسی receipt، روی **Verify latest receipt** بزنید. نتیجهٔ `VALID` نشان می‌دهد فایل receipt از زمان ساخت با provider امضای محلی Alpha تغییر نکرده است. نتیجهٔ `INVALID` یعنی فایل receipt را نباید مبنای اعتماد قرار دهید.

## ۴. پروژه‌ها، entitlement و قابلیت‌ها

هستهٔ Alpha از پروژه‌های `.dsproj` نسخه‌دار پشتیبانی می‌کند. این archive از Parquet برای داده و JSON برای metadata استفاده می‌کند، با atomic save نوشته می‌شود و در overwrite یک فایل backup با پسوند `.bak` نگه می‌دارد. UI ذخیره/بازکردن پروژه در برنامهٔ هفتهٔ دوم توسعهٔ کامل‌تر می‌شود؛ تا آن زمان، این API عمدتاً برای توسعه و integration آماده است.

Entitlement Alpha برای feature gate محلی وجود دارد. stateهای `active`، `grace` و `expired` در هسته مدل شده‌اند. در حالت expired، ویژگی‌های gated مانند verified export اجرا نمی‌شوند. Alpha هنوز payment، حساب کاربری آنلاین یا license refresh server ندارد.

## ۵. لاگ‌ها و ثبت خطا

DataSense logهای ساختاریافتهٔ محلی را به‌صورت JSONL با rotation نگه می‌دارد. محل دقیق ذخیره‌سازی را سیستم‌عامل تعیین می‌کند؛ در Windows معمولاً در AppData مربوط به DataSense و زیرپوشهٔ `logs` قرار می‌گیرد. فایل‌های کلیدی عبارت‌اند از `datasense.jsonl` و `errors.jsonl`.

| فایل | کاربرد | زمان مراجعه |
|---|---|---|
| `datasense.jsonl` | رویدادهای عملیاتی aggregate، مانند import یا completion quality check | عیب‌یابی یک رفتار تکرارشونده |
| `errors.jsonl` | error ID، component، نوع خطا، پیام و context redacted | زمانی که برنامه یک Error reference نشان می‌دهد |
| `datasense.jsonl.1` تا `.5` | نسخه‌های قدیمی‌تر log پس از rotation | بررسی رخدادهای قدیمی‌تر |

اگر پیام خطا همراه با `Error reference` دیدید، آن شناسه را یادداشت کنید. برای گزارش پشتیبانی، نسخهٔ برنامه، گام‌های تکرار، زمان تقریبی رخداد و error ID را ارائه دهید؛ فایل CSV یا دادهٔ خام را فقط پس از بررسی سیاست محرمانگی سازمان خود ارسال کنید.

## ۶. عیب‌یابی

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| برنامه در Windows هشدار ناشر ناشناس می‌دهد | Alpha بدون code-signing منتشر شده است | checksum را بررسی کنید؛ فقط از صفحهٔ Release رسمی دریافت کنید؛ برای محیط production استفاده نکنید. |
| CSV import نمی‌شود | encoding، delimiter، header یا ستون تکراری | فایل را UTF-8 کنید، delimiter را اصلاح کنید و نام ستون‌ها را یکتا سازید. |
| Verified export blocked است | rule critical/high شکست خورده است | جدول quality را بخوانید، داده/contract را اصلاح کنید و check را دوباره اجرا کنید. |
| Receipt INVALID است | receipt تغییر کرده یا provider محلی تغییر یافته است | به receipt اعتماد نکنید؛ export جدید بسازید و artifact را دوباره بررسی کنید. |
| Readiness score پایین است | missing value، identifier احتمالی یا outlier IQR | هشدارها را بررسی کنید؛ حذف خودکار انجام ندهید و علت کسب‌وکاری را مشخص کنید. |
| برنامه error reference می‌دهد | خطای محلی ثبت شده است | شناسه را حفظ کنید، `errors.jsonl` را با احتیاط بررسی کنید و اطلاعات حساس را حذف کنید. |

## ۷. محدودیت‌های شناخته‌شدهٔ Alpha

Alpha تنها فایل‌های delimiter-separated را از UI import می‌کند، preview را به ۱۰۰ ردیف محدود می‌سازد، امکان collaboration یا sync cloud ندارد و خروجی receipt را با provider محلی Alpha امضا می‌کند. code-signing Windows، license service آنلاین، installer production، پروژه‌های UIمحور و data connectorهای database در برنامهٔ تکاملی بعدی قرار دارند.

ماژول‌های پیشرفتهٔ مالی مانند ARIMA، GARCH، VaR، بهینه‌سازی پرتفوی و مدل‌های فازی در Alpha تصمیم یا توصیهٔ معاملاتی تولید نمی‌کنند. `DataReadinessInsightsModule` صرفاً readiness محلی و توصیفی را بررسی می‌کند.

> این راهنما یک سند استفادهٔ نرم‌افزار است و مشاورهٔ مالی، حقوقی یا سرمایه‌گذاری شخصی ارائه نمی‌کند.
